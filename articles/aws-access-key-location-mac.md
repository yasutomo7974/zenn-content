おはようございます、YASUです。

TerraformやAWS CLIは、普通に動いています。でも、そのアクセスキーが自分のMacのどこに保存されているのか、実は分かっていませんでした。ポートフォリオのGitHub Actionsの設定を見直していたときに、このことが気になったので、実際に確認しました。ついでに、「公開リポジトリに、AWSのアカウント番号が見えていないか」も調べました。今回も、コマンドの意味をAIに解説してもらいながら、1ステップずつ進めました。

## 結論

自分のMacのアクセスキーは、Macの中の専用ファイルに保存されていました。GitHub ActionsはOIDCなので、キーを持っていません。そして、公開リポジトリのREADMEの図(画像)と設定ファイルに、アカウント番号が入っていたので、図のほうから番号を消して、公開し直しました。

## 1. 自分のMacのキーは、どこにあるか

次のコマンドで、設定を確認しました。

```bash
aws configure list
```

「AWSの設定を、一覧で見る」コマンドです。見るだけで、何も変更しません。結果の一部は、次のとおりです(キーは伏せ字です)。

```
access_key : ****************XXXX : shared-credentials-file
secret_key : ****************XXXX : shared-credentials-file
region     : ap-northeast-1       : config-file
```

`shared-credentials-file`と出ているので、アクセスキーは、Macの`~/.aws/credentials`という専用ファイルに、保存されていることが分かりました。TerraformやAWS CLIが動くのは、このキーを使っているからです。

## ルートユーザーのキーではないか確認する

次のコマンドで、「今、どのユーザーとしてAWSに入っているか」を確認しました。

```bash
aws sts get-caller-identity
```

結果のArnの行が、`:user/`で終わっていたので、IAMユーザーのキーで、ルートユーザーではありませんでした。

## 入り口は、2つある

| 入り口 | 認証の方法 |
|---|---|
| GitHub Actions(ポートフォリオの自動デプロイ) | OIDC(キーを保存しない) |
| 自分のMac(Terraform、AWS CLI) | アクセスキー(Macに保存) |

OIDCを使っているのは、GitHub Actionsから入るときだけです。自分のMacはGitHubではないので、別の鍵が必要です。

## 2. 公開リポジトリに、アカウント番号が見えていないか

ポートフォリオのリポジトリは公開(Public)なので、アカウント番号(12桁の数字)が見えていないか、次のコマンドで探しました。

```bash
grep -rnE "[0-9]{12}" . --include="*.md" --include="*.html" --include="*.yml" --include="*.js" --include="*.css"
```

- grepは、ファイルの中から文字を探すコマンド
- `-r`は、フォルダの中を全部探す、`-n`は、行番号も表示する、という意味
- `[0-9]{12}`は、「数字が12桁続く部分」。アカウント番号は12桁なので

結果、GitHub Actionsの設定ファイル(deploy.yml)の、ロールの名前の中に、番号が見つかりました。また、READMEのアーキテクチャの図(画像)にも、番号が書かれていました。画像は、grepでは探せないので、目で見て確認しました。

## 図の画像から、番号を消した

図の画像は、AWSの枠の下に「アカウント番号 / リージョン名」と書かれていました。番号の部分だけを消して、リージョン名だけが残るようにしました。そのあと、次の順番で公開しました。

1. 画像を、同じ名前で上書きする
2. `git add`で、その画像だけを選ぶ
3. `git commit`で、履歴に残す
4. `git push`で、GitHubに送る

pushすると、GitHub Actionsが動いて、公開サイトも更新されます。Actionsタブで、緑のチェックを確認しました。READMEの図と、サイトの実績カードの図の、両方から、番号が消えていました。

## 設定ファイルは、今回はそのままにした

deploy.ymlのほうは、今回は、変えていません。調べて分かったことは、次のとおりです。

- アカウント番号は、パスワードやアクセスキーとは違い、それだけでAWSに入れるものではない
- 実際の守りは、ロールの信頼ポリシーで、使えるリポジトリとブランチを絞っていること
- 過去のコミットの履歴には、古い内容が残る。完全に消すには、履歴を書き換える大がかりな作業が必要

ただ、公開しなくて済むものは、公開しないほうが無難なので、余裕があるときに、ファイルに書かない形に直そうと思います。

## まとめ

- 自分のMacのアクセスキーは、`~/.aws/credentials`に保存されている(`aws configure list`で確認)
- `aws sts get-caller-identity`で、IAMユーザーかルートユーザーかを確認できる
- GitHub ActionsはOIDCでキーなし、自分のMacはキーあり、と入り口ごとに方法が違う
- 公開リポジトリは、grepで文字を探し、画像は目で見て、アカウント番号を確認する
- 画像から番号を消して、pushしたら、Actionsで自動公開された

公開するものに、何が写っているかを確認する習慣が、ついてきました。それでは、また明日!
